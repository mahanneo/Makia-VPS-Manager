# Makia SSTP integration — staging/UAT only

SSTP integration adds authentication-protected API diagnostics, user creation/revocation, account delivery text and a dashboard workspace. It does not install or activate an SSTP daemon. Never advertise working SSTP based only on a menu entry.

## Confirmed VPS constraints (2026-10-26)

- Production locally built 1.6.9, GitHub main 1.6.5
- Nginx owns wildcard TCP/443 IPv4 and IPv6 on the only public IPv4 address
- accel-pppd SSTP daemon is not installed
- Existing HTTPS, Browser VPN, Xray and other users must remain unchanged

## Activation gates

1. Provision a dedicated publicly routed IPv4 and matching trusted DNS/TLS certificate. Because Nginx currently binds wildcard 443, change listener ownership only during an authorized maintenance window with tested rollback. Arbitrary Nginx HTTP reverse proxies are not proven SSTP demultiplexers.
2. Test a pinned accel-ppp SSTP daemon in a separate staging environment, enabling SSTP, auth_mschap_v2, chap-secrets, PPP IP pool, forwarding and NAT. Do not enable PPTP.
3. Set the SSTP bind to dedicated IPv4, port 443, host-name to the verified DNS name, and ssl-pemfile and ssl-keyfile to valid certificate material; configure a dedicated root-only 0600 chap-secrets file at /etc/makia-vps-manager/sstp-chap-secrets. Do not casually mix RADIUS and chap-secrets authentication.
4. Verify exact TCP listener ownership, certificate SAN, expiry and TLS handshake, PPP MS-CHAPv2 negotiation, DNS, real exit-IP, and account revocation/connected-session termination.
5. SSTP diagnostics must return ready=true before creating users. Unprovisioned hosts keep the Create button disabled.
6. On Windows 10/11, test built-in SSTP with certificate validation enabled, correct server identity, IP and DNS routing, restart, and failure handling.
7. Off-host encrypted backup, rollback demonstration, complete CI and explicit production deployment authorization are mandatory.

## Application safeguards

- The existing management auth, CSRF and same-origin validation apply to SSTP mutating APIs.
- Usernames/passwords are validated; a dedicated chap-secrets store is updated atomically with 0600 permissions.
- SSTP has a separate Access Center user list and confidential native text export, not a fictitious Apple mobileconfig.
- Removing credentials prevents new logins but does NOT automatically disconnect existing PPP sessions. The API reports that limitation explicitly.
