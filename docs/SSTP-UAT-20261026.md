## Real-client findings

### Android

Open SSTP Client authenticated as user001 and established a PPP tunnel with an assigned address in the 10.79.0.0/24 pool. The earlier client status showed DNS as not specified; DNS advertisement was added on the server and the SSTP backend restarted successfully. The user subsequently reported the connection came up. **A post-change public egress-IP and DNS lookup from the handset has not yet been independently captured**, so full data-plane UAT remains open.

### Windows built-in SSTP — FAIL / release blocker

Windows reports RasClient error 720. Server logs show TLS/SSTP and MS-CHAPv2 authentication succeed, then the server sends an IPCP Configure-Request for 10.79.0.1; the Windows client sends LCP TermReq before sending its own IPCP Configure-Request. This is not a password or TLS handshake failure. The root cause is not yet proven; the remaining investigation must distinguish a local Windows PPP/WAN Miniport stack issue from server/client IPCP compatibility.

Do not claim native Windows SSTP is production-verified until a real Windows client completes IPCP, receives IP/DNS, and passes a public egress test with certificate validation enabled.

## Required release gates

1. Resolve Windows native SSTP error 720 and capture successful IP/DNS assignment and real internet egress.
2. Repeat Android connect/disconnect after the DNS change; capture a successful DNS lookup and public exit-IP from the handset.
3. Create an encrypted off-host backup of current data/config/runtime, verify its checksum and restore/decryption, and demonstrate the documented rollback path.
4. Run full CI on the exact release commit, including clean install and upgrades; rerun host smoke and Doctor after deployment.
5. Promote the exact tested source to main, publish an immutable v1.6.10 release/tag, and verify the live app version and source tree match that release. Do not auto-publish unrelated Android/Windows client artifacts.
6. Retain a time-bounded rollback window and preserve existing VPN listener/process identities.

## Application safeguards

- Existing management authentication, CSRF and same-origin validation apply to mutating SSTP APIs.
- Usernames/passwords are validated; the dedicated chap-secrets file is updated atomically with mode 0600.
- SSTP has its own Access Center user list and confidential native connection text; do not generate a fictitious Apple mobileconfig.
- Removing credentials prevents new logins but does not automatically disconnect an existing PPP session; the API must continue to report that limitation.
- Never enable PPTP or change the existing Nginx TCP/443 listener as a shortcut.
