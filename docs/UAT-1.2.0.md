# Makia VPS Manager v1.2.0 — UI, Collision Preflight, Telegram Proxy & DNS UAT

Date: 2026-09-29  
Branch: `feat/v1.2-ui-proxy-dns-preflight`  
Target: `1.2.0`

## Scope

v1.2.0 hardens creation workflows and adds two optional network services without running privileged package installation from the hardened Makia web process.

### UI / UX
- Fixes the literal `undefined` protocol-card label in Create Access.
- Replaces the invalid missing icon slot with the shared protocol SVG glyph.
- Adds bounded/wrapping protocol-card copy.
- Makes the Xray preset library full-width and responsive.
- Prevents preset labels, notes and form controls from colliding at desktop/tablet/mobile widths.
- Keeps management modals above the fixed sidebar.

### Collision preflight
- Suggested access names are checked across SSH, Xray/Outline managed clients, WireGuard and OpenVPN.
- Direct WireGuard/OpenVPN/Outline/legacy-Xray creation consumes the collision-safe default suggestion.
- Xray performs an authoritative port check again at commit time.
- Busy requested ports are replaced by a free managed candidate according to transport requirements.
- Hysteria/mKCP checks UDP; normal Xray transports check TCP; SOCKS/Shadowsocks check both where required.
- Persisted artifact metadata records the actual selected port, not the stale requested port.

### Telegram Proxy
- Optional Telegram MTProto proxy uses pinned `mtg v2.2.8`.
- amd64/arm64 release archives are SHA256 pinned.
- FakeTLS secrets are generated by `mtg generate-secret --hex`.
- Secret lives in `/etc/makia-vps-manager/mtproxy.toml`, mode 0640, readable only by root and the dedicated `makia-mtproxy` group.
- The secret is not placed in the systemd command line or environment.
- Runtime uses dedicated `makia-mtproxy` user and only `CAP_NET_BIND_SERVICE`.
- Panel provides service/listener state, QR, `tg://proxy` and `https://t.me/proxy` links.
- Re-saving an active proxy preserves its current port.
- A genuinely occupied requested port receives a collision-free fallback.
- Rotating the secret intentionally invalidates old customer links.
- Initial/root install remains an explicit host command: `sudo makia-install-mtproxy --host <hostname>`.

### DNS
- Optional resolver uses Unbound with DNS-over-TLS upstreams.
- Presets: Cloudflare, Quad9, Google.
- Private mode listens on localhost and, when present, WireGuard address.
- Public mode requires explicit source IP/CIDR allowlist.
- Open resolver configuration is intentionally blocked.
- UFW rules are source-scoped; Makia never adds an unrestricted public port-53 allow rule.
- Unbound config is validated before restart and rolled back on apply failure.
- The panel reports resolver state, addresses and local query latency.
- DNS can improve name-resolution/cache behavior; it does **not** guarantee lower game-server RTT or geographic/service-unlock behavior.

## Backup / Disaster Recovery

Full Migration includes:
- `/opt/makia-mtproxy`
- `/etc/makia-vps-manager/mtproxy.env`
- `/etc/makia-vps-manager/mtproxy.toml`
- Makia Unbound state/config
- `makia-mtproxy.service`

Restore refuses to claim readiness when corresponding host runtime dependencies are absent. Install the optional component on the replacement host before restoring that component's runtime state.
