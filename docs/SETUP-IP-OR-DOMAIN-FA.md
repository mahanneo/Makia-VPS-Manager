# راهنمای مرحله‌ای: نصب Makia با IP یا دامنه

> وضعیت: راهنمای نسخه کاندیدای IP/Domain. سرورهای دارای NAT، پروتکل‌های TLS، و شبکه اپراتورها نیاز به تست واقعی دارند.

## ۱. انتخاب آدرس پنل

| روش | مناسب برای | محدودیت |
| --- | --- | --- |
| `http://PUBLIC_IPV4/` | ورود اولیه و تنظیم روی شبکه مورد اعتماد | **HTTP رمزگذاری ندارد**؛ رمز مدیر را روی اینترنت ناامن وارد نکنید |
| `https://panel.example.com/` | اداره روزمره و دسترسی کاربرها | دامنه، رکورد A مستقیم، پورت TCP/443 و گواهی معتبر لازم است |
| `https://PUBLIC_IPV4/` | فقط با گواهی TLS معتبر دارای IP SAN | گواهی مخصوص IP لازم است؛ استفاده از گواهی دامنه برای IP خطای TLS ایجاد می‌کند |

برای NAT ابتدا IP عمومی ارائه‌شده توسط سرویس‌دهنده را پیدا کنید. IPهای `10.x.x.x` و `192.168.x.x` آدرس عمومی قابل اتصال نیستند. هنگام نصب جدید می‌توانید `MAKIA_PUBLIC_IPV4` را وارد کنید:

```bash
sudo MAKIA_PUBLIC_IPV4=YOUR_PUBLIC_IPV4 bash install.sh
```

اگر نصب قبلاً انجام شده، در فایل **root-only** زیر مقدار را اضافه کنید:

```text
/etc/makia-vps-manager/makia.env
MAKIA_PUBLIC_IPV4=YOUR_PUBLIC_IPV4
```

پس از افزودن تنظیم، برای به‌روزرسانی پیشنهادها نیاز به Restart کنترل‌شده سرویس وب Makia دارید، نه Restart تونل کاربران. پورت‌های مدیریتی نباید با سرویس‌های VPN تداخل داشته باشند.

### دسترسی هم‌زمان با IP و دامنه (Nginx)

نصب تمیز دو ورودی جدا می‌سازد: درخواست IP روی HTTP/80 وارد Virtual Host پیش‌فرض می‌شود و دامنه برای HTTPS/443 با Certbot پیکربندی می‌شود؛ تغییر دامنه نباید مسیر IP اولیه را به HTTPS با گواهی اشتباه هدایت کند.

روی **نصب‌های قدیمی** برای انتقال حفاظت‌شده و اختیاری، ابتدا بکاپ کامل و وضعیت Nginx را بررسی کنید و فقط در پنجره نگهداری مناسب اجرا کنید:

```bash
sudo nginx -t
sudo makia-backup
sudo makia-enable-ip-panel
```

این فرمان از سایت Nginx نسخه پشتیبان می‌گیرد، تنها `default_server` پورت ۸۰ را از سایت دامنه جدا می‌کند، fallback مستقل IP را نصب می‌کند، سپس `nginx -t` و پاسخ `/healthz` را می‌سنجد. هنگام شکست باید Nginx قبلی را برگرداند. **HTTPS/443 و پروتکل‌ها را Restart نمی‌کند**. این مرحله برای سرورهای مشترک با وب‌سایت‌های دیگر حتماً باید ابتدا روی Staging تست شود؛ `default_server` دیگری ممکن است با آن تداخل کند.

## ۲. راهنمای فرم ساخت پروتکل

در پنل، برای ساخت SSH، Xray، WireGuard یا OpenVPN، «آدرس اتصال کاربر» را انتخاب کنید:

1. **IP عمومی:** برای اتصال مستقیم بدون DNS؛ آدرس عمومی VPS را وارد کنید.
2. **دامنه:** رکورد A باید به VPS اشاره کند. برای SSH / WireGuard / OpenVPN خام و Shadowsocks معمولاً DNS Only (بدون Proxy/CDN) استفاده کنید.
3. **Port:** شماره پورتی است که سرویس واقعاً روی آن گوش می‌دهد؛ صرفاً عدد ۴۴۳ یا ۱۱۹۴ را بدون تطبیق با Listener انتخاب نکنید.
4. پیش از ساخت، هشدارهای IP، DNS و گواهی را بخوانید. بعد از ساخت با یک حساب تست، کانفیگ واقعی را از شبکه خارجی امتحان کنید.

`/api/protocols/connection-setup` برای کاربر ادمین پیشنهاد IP/Domain و هشدارها را ارائه می‌کند. `/api/protocols/endpoint-matrix` وضعیت مقدماتی سمت سرور را بررسی می‌کند، **نه اتصال قطعی کلاینت**.

## ۳. پروتکل‌ها و انتخاب امن

| پروتکل | IP عمومی | دامنه | پیش‌نیاز |
| --- | --- | --- | --- |
| SSH و NPV | بله | بله | TCP/22 یا پورت واقعی SSH، حساب معتبر؛ SSH به‌تنهایی VPN کل دستگاه نیست |
| WireGuard | بله | بله | UDP و NAT/Forwarding سالم، کلید peer و Port درست |
| OpenVPN خام | بله | بله | UDP/TCP و PKI فایل OVPN، Port واقعی؛ گواهی OpenVPN با HTTPS پنل یکی نیست |
| Xray VLESS + REALITY | معمولاً بله | بله | SNI و پارامترهای REALITY و تنظیم دقیق Core؛ IP اتصال لزوماً SNI نیست |
| Xray با TLS، Trojan، Hysteria2 | فقط اگر گواهی با IP سازگار باشد | توصیه‌شده | گواهی معتبر و SNI/ALPN مطابق تنظیمات؛ UDP برای Hysteria2 |
| OpenVPN over WStunnel/HTTPS | در حالت فعلی نیازمند نام TLS | بله | دامنه دارای گواهی معتبر، مسیر Gateway 443 و Runtime WStunnel |
| IKEv2/IPsec | بله با هویت گواهی سازگار | بله | گواهی/Identity منطبق و UDP/500 و UDP/4500 |
| Outline | ممکن است | ممکن است | پورت و کلید صادرشده واقعی، خام و معمولاً بدون HTTP proxy |
| **PPTP** | **پیشنهاد و فعال‌سازی ندارد** | **پیشنهاد و فعال‌سازی ندارد** | قدیمی، ناامن (MS-CHAPv2) و پشتیبانی ضعیف/حذف‌شده روی iOS؛ جایگزین IKEv2 / WG / OpenVPN |

پشتیبانی ظاهری از IP بدون TLS صحیح نشانه اتصال امن نیست. همچنین هیچ نرم‌افزاری نمی‌تواند عبور موفق در **همه اپراتورها و همه مسیرهای فیلترینگ** را تضمین کند.

## ۴. تست و رفع خطا به زبان ساده

| پیام یا نشانه | علت احتمالی | اقدام |
| --- | --- | --- |
| `Could not resolve host` | DNS/دامنه اشتباه | رکورد A، TTL، DNS Only و DNS Client را بررسی کنید |
| `Connection refused` | Port/Listener بسته | `ss -lntup` و فایروال را بررسی کنید |
| `Connection timed out` | فایروال، NAT، ISP یا مسیریابی | از اینترنت خارجی و شبکه دوم تست کنید |
| `certificate verify failed` | دامنه/IP، SNI یا Certificate نامعتبر | هویت TLS را اصلاح کنید؛ اعتبارسنجی TLS را خاموش نکنید |
| `ERR_TUNNEL_CONNECTION_FAILED` | HTTP CONNECT، احراز هویت Gateway یا مقصد | افزونه جدید Chrome را تست کنید؛ لاگ امن Gateway را ببینید |
| WireGuard handshake بدون اینترنت | Forward/NAT/AllowedIPs/DNS | handshake و counter را هم‌زمان در کلاینت و سرور بررسی کنید |
| «متصل» ولی IP تغییر نمی‌کند | فقط Control Plane فعال شده | با `https://api.ipify.org` و دانلود واقعی ترافیک را بررسی کنید |
